# 拾语 · Shiyu

一个免费、开源的 Android DeepSeek 聊天客户端。把旧对话带过来，继续聊。

**[⬇️ 直接下载安卓安装包 APK（v0.1.7）](https://github.com/Mary253j/shiyu-chat/releases/download/v0.1.7/shiyu-0.1.7-android-arm64.apk)**

适用于 Android 7.0 及以上的 ARM64 手机。下载后打开 `.apk` 文件安装；当前为测试版。

**软件的全部功能免费。DeepSeek API 费用由用户直接向 DeepSeek 支付。自愿打赏不解锁任何功能。**

本项目由 [Mary253j](https://github.com/Mary253j) 维护，采用 MIT 许可证。当前版本为 **0.1.7 GitHub 预发布版**，修复 AI 回复正文中零宽度排版指令逐字显示的问题。仅面向 Android，iOS 暂缓，未通过应用商店分发。

## 不需要搭建服务器

```text
用户手机 ── 用户自己的 API Key ──> DeepSeek 官方 API
   │
   └── 本机加密聊天记录 / 系统安全密钥存储
```

没有作者的 API 中转、共用 Key、用户注册系统、额度账户、广告、遥测或聊天云同步。软件通过系统文件选择器导入记录、选择附件和保存备份。0.1.3 的附件由手机直接上传到 DeepSeek 官方 Files API，使用现有 Key；远端附件存储不等于本应用提供聊天云同步。用户主动导出的是明文文件，必须妥善保管。

编译 APK 可以使用自己的 Android 开发环境，也可以使用 EAS 托管构建；编译工具与聊天运行服务器无关。源码与安装包分别通过 GitHub 仓库和 Releases 分发，不要求用户运行开发服务器。

## 当前功能

- 手机直连官方接口，验证 Key 和查询账户余额。
- 文字流式回答、深度思考、停止生成、失败重试、Markdown、复制回复。
- Flash / Pro 模型选择；上下文默认“自动”，按模型容量发送当前会话可用的历史文字，并预留输出空间，显示历史取舍统计。
- Flash 模式下选择图片、PDF、Word、PowerPoint、表格或文本等附件，发送消息时上传到 DeepSeek 官方 Files API，不需要额外 Key。
- 会话新建、搜索、重命名、删除。
- 消息单条删除、选择多条后批量删除；确认时显示条数，仅删除选中的消息。
- 官方 ZIP v3、常见旧版 JSON 和本应用备份导入；先预览、再合并，不覆盖已有同源记录。
- 本地 AES-256-GCM 加密记录，SecureStore 保存 Key 与数据库密钥，关闭 Android 系统自动备份；0.1.2 改为原生异步加密，索引、会话和原始导入数据分别保存。
- Android 文件夹选择器导出备份；导出文件不加入设置中保存的 Key 或数据库密钥。
- “请作者吃个鸡腿🍗”支持页：包含作者提供的微信／支付宝二维码原图，可切换查看；未进行实际付款测试。

暂不包含联网搜索、语音、自动长期记忆或跨设备同步，尚未完成官方客户端的全部功能。与官方回复不保证完全一致。各版本的最终构建和验证结果以对应 Release 为准。

## 0.1.7：回复排版修复

部分回复在文字间带有 `\hspace{0cm}` 等零宽度排版指令，旧版会逐字显示出来。新版在 AI 回复正文的 Markdown 显示阶段识别零值 `cm`／`pt` 的 `\hspace`，包括带星号、零小数及空白的形式，使正常文字连续显示。例如原始正文 `今\hspace{0cm}天天气很好。` 显示为“今天天气很好。”。

已有导入对话会自动使用新的显示方式，**不需要重新导入记录**。代码示例、显式转义的字面示例、Markdown 链接地址及直接写出的 HTTP(S) 地址保留；非零间距与其他指令不作此处理。这是特定排版指令的显示兼容，不是完整 TeX 公式渲染。用户消息、思考纯文本、复制内容、保存、备份和后续 API 上下文继续使用原始文字，导入与存储流程不变。

0.1.7 已通过 TypeScript、ESLint 和 159 项核心测试，含 8 项新增排版回归。Web 生产导出、34 项桌面／手机浏览器 UI 测试及 APK 构建和签名核验也已通过，见 [0.1.7 发布说明](docs/releases/v0.1.7.md)。

## 0.1.6：ZIP 导入内存修复

此前导入官方 ZIP 时会一次读取整个文件；约 49.5 MiB 的文件也可能触发 Android 内存分配失败，而放宽容量上限并不能解决这个问题。新版改为最多 64 KiB 一次读取，先检查 ZIP 目录和文件头，再逐段解析会话；附件分块解压、校验后丢弃，不把整份附件留在内存。路径、大小、索引和 CRC 校验继续保留，整个压缩包通过验证后才显示导入预览。

确认合并时按会话检查备份格式与总容量，不再为检查而把旧记录和新记录整库序列化、再解析一遍。读取、校验、整理和保存显示进度，内存不足时显示中文提示。预览或合并校验失败不会修改已有记录；相同来源仍跳过，不会自动覆盖已有对话，包括已有的空对话。

**1 GiB 是容量检查上限，不是手机内存保证。** 已加载的会话仍保留在内存，单段特别大的会话仍需完整解析；纯 JSON 采用分块读取，但仍需组装全文后解析，实际导出备份也仍会生成整库 JSON。上述情形仍可能内存不足。本次没有改变附件上传的 20 MiB 限制、消息删除或键盘行为，也没有自动恢复旧 ZIP 的附件原件。

0.1.6 已通过 TypeScript、ESLint 和 151 项核心测试，包括约 52 MiB 合成 ZIP 的小块读取、附件 CRC 校验与导入失败保护；Web 生产导出、32 项桌面／手机浏览器 UI 测试及 APK 构建和签名核验也已通过，见 [0.1.6 发布说明](docs/releases/v0.1.6.md)。

## 0.1.5：删除消息与键盘布局

可删除单条消息，也可通过明确的选择按钮进入多选，勾选消息后一次确认删除。确认框显示所选条数，只删除选中的消息；未选中的消息继续显示，不自动连带删除相邻问答。删除成功后，被删消息不再作为后续聊天上下文；程序保留删除形成的边界，避免把缺口两侧的消息错误配成一轮对话。

删除也会处理应用保存的原始导入资料。能识别的 `messages`／`mapping` 结构会清除选中节点的正文等内容并保留结构关系；无法安全逐条清理的原始副本会被整体移除，并显示提示，其他未选中的可见聊天仍保留。**这是删除选中记录，不是对同一内容做全文清除**：未选消息、其他分支或原始资料顶层其他字段中的引用和复述不会被搜索改写。删除保存后不保留能恢复选中记录的前代引用，文件清理失败会在后续读取或保存重试。此前导出的备份、用户原 ZIP、已经发给 DeepSeek 的内容和 Files API 文件不会随之删除，也不承诺物理擦除手机闪存。

针对键盘弹出后遮住输入区、需要先收起键盘才能点击发送的问题，调整聊天页的键盘避让和窗口缩放；键盘显示时隐藏底部导航，给输入区留出空间。**尚未完成 OPPO 真机验证**，不把浏览器模拟结果作为该手机修复效果的证明。

0.1.5 沿用了 0.1.4 的 1 GiB（1024 MiB）容量上限，但当时仍整包读取，未解决导入内存峰值。0.1.6 的 ZIP 读取方式调整见上节；仍未验证手机稳定导入 1 GiB。聊天附件仍为单个最多 20 MiB、每条消息最多 4 个。

变更与验证状态见 [0.1.5 发布说明](docs/releases/v0.1.5.md)。

## 0.1.3：附件与历史续聊

旧版默认最多取最近 40 条上下文，导入后的长对话可能没有把较早文字发给模型。新版默认改为“自动”，旧设置也迁移到此模式：在 1M 上下文窗口内预留回复和安全空间后，按文本估算容量尽量使用当前会话、当前分支的可用历史；超出预算时保留较近内容，并显示截断统计。仍可手动选择只带最近消息。附件展开后的 token 数无法在手机端预先准确计算，带附件的请求仍可能遇到平台上下文限制。

续聊不跨会话查找，也不发送其他分支、原始导入 JSON 或历史思考过程。孤立的用户消息和明确可用的导入中断回复可以参与上下文；失败、拒答和不可用的未完成回复不参与。历史附件缺失时，如原会话保留了可用的 AI 总结，可在注明原件不可用的前提下引用总结；这不等于恢复附件，也不能保证模型记得所有细节。

附件目前只在 Flash 使用，每条消息最多 4 个、单个最多 20 MiB。支持 JPG/JPEG、PNG、GIF、WebP 图片，PDF、DOC/DOCX、PPT/PPTX，以及 XLS/XLSX、TXT、Markdown、CSV、JSON、EPUB、MOBI 和常见源码／文本格式。PDF、Word 和 PowerPoint 默认采用图文解析，可利用识别出的文字与图片；不能保证每个图表、图形或版式都被完整识别。

先选择文件，点击发送并通过本地上下文检查后才上传；仅打开选择器不会上传。选择器会建立临时缓存副本，成功提交聊天或主动移除草稿等操作后清理，不删除用户源文件；失败时保留草稿便于重试。解析成功可能产生独立于聊天生成的费用，取消等待不保证撤销已发生的费用或删除已上传的文件。DeepSeek Files API 默认永久保留文件，应用不会因删除本地聊天而自动删除远端文件，使用前请确认内容适合交给 DeepSeek 处理。

**请保留附件源文件。** 本地聊天及导出备份保存的是文件名、类型、大小和 `file_id` 等引用信息，不包含附件原件；官方 Files API 也不提供下载原件或解析结果的能力。换用其他 DeepSeek 账户、远端文件被删除或引用失效后，需要重新选择源文件上传；本地备份不能重新生成它。旧版导入 ZIP 时没有迁移的附件原件，也不会在更新后自动补回。

具体行为与未验证项见 [0.1.3 发布说明](docs/releases/v0.1.3.md)。官方接口说明：[Files API](https://api-docs.deepseek.com/guides/files_api/)、[文档解析](https://api-docs.deepseek.com/guides/document_parsing/)、[视觉理解](https://api-docs.deepseek.com/guides/vision/)。

## 0.1.2 改动

0.1.2 针对导入较多历史后，输入、切换对话和滚动容易卡顿的问题调整保存与展示方式，0.1.3 保留这些改进：

- 本地保存改为原生异步加密和按会话更新，原始导入数据独立保存，减少聊天过程中重复处理整库数据。
- 长会话使用虚拟列表，并合并流式消息更新，减少重复绘制。
- 打开对话直接定位最新消息；上翻阅读历史时，新回复不强制拉回底部，可点击“回到最新”继续跟随。
- 保持本地加密，自动迁移现有记录；正常覆盖升级不要求重新导入历史。

合成数据和桌面测试用于排查瓶颈，不能当作 OPPO 或其他手机的实际性能结果。大量历史的首次读取、格式迁移及备份仍可能需要时间。迁移在首次加载后的保存中完成，旧文件在新格式成功提交前保留；保存失败时请保留数据并反馈，不要通过清空记录来尝试修复。技术细节见 [存储格式与迁移设计](docs/storage-format.md)。

## 记录迁移的边界

支持 DeepSeek 当前公开的 `export_format_version: 3` ZIP，以及测试覆盖的旧版 JSON 数组、`conversations` 包装与 `mapping` 消息树。不会通过 Key 自动读取官方账户历史，也不收集 DeepSeek 登录密码。

导入时会保留完整原会话 JSON（包括非当前分支）为 `originalData`，当前分支的文字与思考用于展示。自 0.1.2 起，原始 JSON 单独加密存储，普通聊天保存时可复用它，导出时包含仍保留的原始资料；0.1.5 删除消息时会清理对应内容，无法安全识别的原始副本会被移除并提示。0.1.3 改善已有文字的上下文选择，但**官方 ZIP 中的图片／文档原件、联网工具上下文仍不会自动迁移到续聊请求**。需要使用原附件时，请重新选择源文件上传。导入预览会报告这些限制，仍应单独保管官方原 ZIP；导入不会声称完全无损。

安全限制：输入文件最多 1 GiB（1024 MiB，界面标为 1 GB）、ZIP 总解压最多 1 GiB，最多 2,000 段对话 / 100,000 条消息，另有限制路径、CRC、嵌套深度与消息长度。单次整库 JSON 备份最多 1 GiB；合并导入前检查是否仍可备份，超限时保留现有数据并拒绝该次导入。0.1.4／0.1.5 仅提高容量上限，0.1.6 改为小块读取 ZIP、逐会话解析，并分块校验附件；已有会话、单段大 JSON 和真正导出备份的内存成本仍存在。未验证 1 GiB 导入，不能保证到达容量上限时仍能稳定处理。大量历史仍建议分批整理。聊天附件上传限制仍为单个 20 MiB。

## 本地开发

需要 Node.js 24、npm。原生工程由 Expo 配置生成，不手工维护 `android/`。

```sh
npm ci
npm run check
npm run web
```

网页只用于界面预览，数据与 Key 存在内存，刷新即清空。它不等价于安卓真机测试。没有配置任何真实 Key；请不要将自己的 Key 写进源码或上传到 GitHub。

生成 Android 开发工程：

```sh
npx expo prebuild --platform android
npx expo run:android
```

这会使用本机 Android SDK。完整发布与托管 APK 构建步骤见 [Android 发布指南](docs/RELEASE.zh-CN.md)。EAS `preview` 配置生成 APK，不是必须依赖开发服务器的 development client。
