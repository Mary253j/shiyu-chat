# 拾语发布指南

更新时间：2026-11-17。本文针对 `Mary253j/shiyu-chat` 的 **0.1.6 ZIP 导入内存修复预发布**，发布 MIT 许可源码和签名 Android APK。目标渠道为 GitHub prerelease，不是应用商店；本文是发布步骤与核对说明，不表示发布或验证已完成。

## 当前版本与范围

拾语是使用用户自己的 DeepSeek API Key 的免费聊天客户端。用户向 DeepSeek 充值，API 费用由用户承担；应用作者不出售 API 额度，也不提供共用 Key。

当前源码范围是文字聊天、思考模式、历史记录导入后的续聊、Flash 模式下的图片和文档附件，以及消息单条／批量删除。它尚未完成 DeepSeek 官方客户端的全部功能，不能宣传为官方客户端、完整替代版或保证回答完全一致的产品。历史记录导入不会自动同步官方账户，也不会转移模型内部状态。

本阶段仅开发和发布 Android，iOS 暂缓，不提供 iPhone 安装包或上架教程。技术方案为 Expo SDK 58、React Native 0.88、TypeScript 的原生 Android 应用。手机直接连接 `https://api.deepseek.com`，没有作者运营的聊天中转服务器、账户系统或云同步。Web 版本仅用于预览，数据保存在内存，刷新或关闭页面后丢失，不能代替原生版验证。

## 0.1.6 ZIP 导入内存修复

针对官方 ZIP 导入时 `FileSystemFile.bytes` 一次分配约 49.5 MiB 而触发 Android `OutOfMemoryError` 的问题，改用 Expo 58 `FileHandle` 随机读取，单次最多 64 KiB。先验证 ZIP 中央目录和本地文件头，再逐段读取、解压和解析会话。附件只作分块解压与 CRC 校验，不保留整份二进制内容；压缩包全部验证通过前不返回导入预览。路径、重复名称、条目数量、大小、索引与校验限制不因这次优化而取消。

确认合并时逐会话执行格式与恢复校验，精确累计最终备份字节、消息数和节点数，检查全局重复 ID；不再为合并检查复制、解析整个新旧记录库。读取与确认阶段显示进度，内存分配失败显示中文提示。预览和合并校验不改写已有记录，重复来源仍跳过，不自动用新导入内容覆盖已有空对话。接受导入后的保存失败应保留内存状态并提示重试，不通过清空记录恢复。

上述流程不改变存储格式或用户 Key，也不把官方附件原件迁移到续聊。1 GiB 仍只是容量上限：已载入的会话对象、单段超大会话和原始资料仍占内存；纯 JSON 分块读取后仍全文解析，实际导出备份仍生成整库 JSON。不得把 64 KiB 读取块大小写成整个导入过程的内存上限，或据此承诺任意 1 GiB 文件均可处理。

## 已有消息删除与键盘布局

单条删除及多选批量删除都要确认，批量确认显示所选条数。通过明确按钮进入多选，只删除选中消息；未选消息继续显示，不自动删除整轮或相邻消息。删除后，这些消息不再进入后续请求，保留的消息通过 `contextBoundaryBefore` 标记删除缺口，防止跨缺口配对。不能以自动改写未选消息或清空整段会话来代替精确删除。

删除同步清理原始导入资料：对于可识别的 `messages`／`mapping` 结构，选中节点仅保留必要结构字段，清除正文、思考、附件等内容；格式无法安全识别时移除该原始副本并提示，未选中的可见聊天保留。范围是选中记录，未选消息、其他分支及原始资料顶层其他字段中的引用或复述不做全文清除。每次有效删除递增 `redactionRevision`，删除提交取消前代和旧格式副本引用；旧密文清理失败后重试，旧版本快照不能覆盖删除后的状态。详情见 [存储格式](./storage-format.md)。旧备份、原 ZIP、已发送给 DeepSeek 的内容及 Files API 文件不自动删除，不宣传安全擦除闪存。

键盘修复在根布局使用键盘避让，原生平台采用 padding；键盘弹出时隐藏自绘底部导航并去掉底部安全区留白，Android 明确使用窗口 `resize`。本次仍只发布 Android，不因此新增 iOS 分发。目标是键盘显示时输入区和发送按钮保持可用；尚未完成 OPPO 真机验证，不用桌面模拟结果替代设备实测。

沿用 0.1.4 的 1 GiB（1024 MiB）导入、ZIP 解压总量及整库备份容量上限，消息数、会话数和格式限制仍适用。0.1.6 优化 ZIP 导入内存峰值，但未验证 1 GiB 导入，不承诺设备可稳定处理该上限。附件限制仍是每个 20 MiB、每条消息最多 4 个。

## 已有附件与上下文行为

附件由手机直接使用用户现有 Key 上传到 DeepSeek 官方 Files API，不需要作者服务器或额外 Key。每条消息最多 4 个、单个最多 20 MiB；只在用户点击发送时上传。当前支持 JPG/JPEG、PNG、GIF、WebP，PDF、DOC/DOCX、PPT/PPTX，XLS/XLSX、TXT、Markdown、CSV、JSON、EPUB、MOBI 和常见源码／文本格式。具体扩展名白名单以 `src/core/attachments.ts` 为准。

PDF、Word 和 PowerPoint 默认使用 `rich_layout_recognition` 图文解析，使用识别出的文字和图片，但不保证每个图表、图形和版式都被完整识别。其他支持格式使用 `user_data`。解析成功可能单独收费；取消等待不保证撤销已发生的费用或删除上传文件。应用不设置自动过期时间，DeepSeek 官方默认永久保留；删除本地聊天不自动删除远端文件。必须在上传前向用户说明这些事实，不把失败后的自动重复上传当作普通无成本重试。

文件选择器使用临时缓存副本，选择时不上传；成功提交聊天、移除草稿、删除对应会话或清空数据时尝试清理，不删除用户源文件。失败保留草稿便于重试；重启不恢复草稿，异常遗留缓存可能待系统回收。这些副本不属于加密聊天数据库，不能宣传为附件从未在设备留下未加密临时文件。

本地加密记录和明文导出备份只含文件名、类型、大小与 `file_id` 等引用信息，不含附件原件。官方 Files API 不提供原件或解析结果下载，换账户、远端删除或引用失效后需用户重新选择源文件。旧版从官方 ZIP 导入时未迁移的附件原件，不能在升级后自动补回；已有完整 AI 总结可在注明原件缺失的前提下参与续聊。

上下文默认从旧版最近 40 条改为“自动”；旧配置缺少 `contextMode` 时也按自动处理，只有用户明确选择最近消息模式才应用对应条数上限。按文本估算容量，在 1M 窗口中预留输出和安全空间，并显示截断统计；文件展开后的 token 数未知，不承诺有附件时绝不超窗。只使用当前会话、当前分支的可用消息，保留孤立用户消息和明确可用的导入中断回复；失败、拒答、本机中断及不可用的截断回复不带入。历史思考过程、原始 JSON 和其他分支不发送。

参考 DeepSeek 官方 [功能更新](https://api-docs.deepseek.com/news/news261113/)、[Files API](https://api-docs.deepseek.com/guides/files_api/)、[文档解析](https://api-docs.deepseek.com/guides/document_parsing/)与[视觉理解](https://api-docs.deepseek.com/guides/vision/)。发布前再次核对实际 API、计费及保留规则。

## 本地存储与旧格式迁移

存储格式升级为 v2，仍使用原有 SecureStore API Key 与 AES 主密钥标识，不通过换密钥来迁移。原生异步 AES-256-GCM 加密索引、每段会话和该会话的原始导入 JSON；原始 JSON 使用独立加密文件，普通消息更新可以复用未变的原始数据。设置或当前会话变化主要更新索引，不再重复加密全部聊天。

加载 v1 时先读取旧记录；首次后续保存才写入 v2。新的会话文件和索引全部成功提交前不删除 v1。首个 v2 提交后保留一份最新 v1 密文，下一次实际产生新 v2 版本的成功保存后移除；没有变更的保存不算一个新版本。

正常保存保留当前索引及最多一代前序引用。删除会话或消息成功提交后，清单不再引用能够恢复被删内容的前序记录和旧版快照，并尝试清理旧正文及被替换的原始资料文件；清理失败会在后续加载或保存时重试。单会话删除版本持久保存，排队的旧快照若版本较低则拒绝写入。因此不承诺闪存即时物理抹除。清除所有本地数据按顺序先删文件、再删密钥，避免删除失败时使剩余文件失去恢复条件。

最新索引、会话或原始数据损坏时应报错并保留文件，不默默回退成更旧内容或空历史。维护者验证迁移中断、写入失败、重启、删除和清空时，都要确认这一行为。旧副本仅用于保护和排查，不代表支持把应用降回 0.1.1 继续使用新格式。

## 本地准备与检查

在项目根目录安装依赖并运行检查；使用仓库的锁文件保持依赖一致：

```sh
npm ci
npx tsc --noEmit
npx expo lint
npx expo-doctor
```

若检查失败，先修复再生成正式构建。模拟器和 Web 预览通过不能代替 Android 真机测试。开发工具中的运行按钮也不等于已经生成可公开分发的正式安装包。

至少在 Android 真机验证：

- 首次启动、用户知情后填写自己的 Key、有效和无效 Key、余额不足、网络中断、停止生成和请求失败后的再次发送。
- 文字与思考模式、长对话、导入真实脱敏样本、导入错误文件时不破坏已有记录、重启后历史恢复。
- 备份导出前显示明文提醒，导出过程不加入设置中保存的 API Key 或本地加密密钥；重新导入能恢复预期的聊天内容。
- 单条与多选删除的确认、取消、条数和精确范围；未选聊天继续显示，被删消息不进入请求，保存及重启后不复活。核对原始资料清理或移除提示，以及备份不恢复已删节点内容。
- 删除记录和清除 Key 后的实际状态，以及卸载、重装、系统备份恢复的行为。不能用删除本地记录代表已删除此前导出的文件或官方远端文件。
- 键盘弹出时，输入、多行文本、发送、页面切换及收起键盘后的导航恢复；OPPO 真机未验证时按实标明，不要求用户承担发布验证。
- 验证 0.1.1 至 0.1.5 → 0.1.6 同签名覆盖升级：记录、Key 和仍保留的导入原始数据保留，不要求重导入 ZIP。0.1.1 旧格式在首次读取后的保存中迁移；迁移中断或失败时应保护旧文件，不能直接变成空历史。
- 验证附件选择与移除不触发上传；发送后图片、文字文档、PDF／Office 解析可用，并检查超限、错误类型、取消、网络失败、无权限／失效 `file_id` 的提示。不得用 mock 测试代替真实计费与远端保留验证。
- 验证备份只含附件引用，不包含原件、临时路径或 Base64；重新导入后说明跨账户与远端删除的限制。旧 ZIP 的原附件仍不自动恢复。
- 验证旧配置转为自动上下文；使用超过 40 条的导入会话检查较早可用文字，检查截断统计、孤立用户消息、可用导入中断回复，以及失败／拒答／其他分支不会混入。
- 使用较多历史和长会话验证输入、切换、发送和保存；检查打开对话显示最新消息、用户上翻时不被新回复拉回、点击“回到最新”后恢复跟随。
- 仅对仍使用不同签名的 0.1.0 测试版保留“先导出并确认备份，再卸载、安装、导入”路径；不能对 0.1.1 至 0.1.5 用户照搬该做法。
- 发布构建不记录 Key、完整提示词或聊天正文；错误提示也不暴露这些内容。

## 从 0.1.1 至 0.1.5 覆盖升级

0.1.6 使用与 0.1.1 至 0.1.5 相同的包名和独立发布签名，本版 APK 的证书一致性已经核验，可直接覆盖安装，不需要卸载，也不需要重新导入 ZIP。建议更新前导出一份明文备份并妥善保管；备份是额外保护，不是正常升级的必经导入步骤。此前导出的备份仍可能包含后来删除的消息。

来自 0.1.1 的旧格式在首次读取后的保存中自动迁移，0.1.2 及之后的分会话存储格式继续使用。维护者应验证旧记录、Key 和仍保留的导入原始 JSON 可读取，以及迁移中断后的恢复行为。旧版尚未设置上下文模式时转为自动，但这不会重新获取官方历史或补回未迁移附件。不要将桌面合成数据耗时写成手机实测指标，不承诺固定毫秒数、帧率或设备性能。

## 从 0.1.0 测试版迁移

0.1.0 使用通用测试签名，0.1.1 及之后使用项目独立发布签名，因此从未升级的 0.1.0 仍不能直接覆盖安装 0.1.6。迁移说明必须随 APK 发布：

1. 在旧版导出聊天备份，保存到应用目录之外，并确认文件可读取。备份是明文，勿公开分享。
2. 确认备份可用后才卸载 0.1.0；卸载会移除原本地数据和密钥，未备份的数据无法由维护者找回。
3. 安装 0.1.6，导入备份并重新填写自己的 API Key。

独立发布签名不等于应用稳定性已完成验证。记录正式 APK 的签名证书 SHA-256 指纹，并持续安全保管该密钥。

## 首选：通过 Expo Build 云构建 Android APK

不需要自行购买或维护构建服务器。Expo Build 是托管编译服务，CLI 仍使用 `eas` 命令；它与运行时的聊天服务是两回事，用户聊天仍由手机直连 DeepSeek。

以下步骤会连接作者自己的 Expo 账户并上传构建所需的项目文件；当前没有代为执行。首次准备构建时先注册并登录账户：

```sh
npx eas-cli@latest login
npx eas-cli@latest build:configure
```

选择 Android，并确认关联的是自己的 Expo 项目。检查 `eas.json`：给直接分发的 APK 配置一个名为 `preview` 的构建 profile，其中 `android.buildType` 应为 `apk`。不要将正式给用户使用的 APK 配置成 `developmentClient: true`。最小配置形式如下；已有其他设置时只合并需要的部分：

```json
{
  "build": {
    "preview": {
      "distribution": "internal",
      "android": {
        "buildType": "apk"
      }
    }
  }
}
```

执行构建：

```sh
npx eas-cli@latest build --platform android --profile preview
```

使用为本项目创建的独立 Android 发布 keystore；如果已经在本地生成，向 EAS 导入同一套凭据，不能重新生成另一套签名。云服务可保管签名凭据，维护者仍应安全备份并了解其保管方式。后续版本沿用相同应用标识和正确签名。[Expo APK 构建配置](https://docs.expo.dev/build-reference/apk/)、[Expo 构建与签名](https://docs.expo.dev/deploy/build-project/)

构建完成后，从 Expo 提供的构建页面下载 APK，在真机验证它不依赖开发服务器即可运行。APK 是可直接安装的文件；默认生成的 AAB 面向支持它的商店，不能直接让用户点击安装。取得 APK 不等于已公开发布 GitHub 仓库，也不等于通过任何应用商店审核。

如果需要开发客户端，应另外使用包含开发客户端配置的 profile。当前 SDK 与所装 Expo Go 的兼容性需要单独核对，不能保证扫描二维码后 Expo Go 就能运行本项目。

构建上传前确保项目没有真实 Key、聊天备份、收款平台密码或无关私人文件。托管构建可能有配额与费用，以所选账户方案为准。

## 备用：Android 本地开发与签名构建

### 1. 准备构建环境

安装 Android Studio、所需 Android SDK 和与当前 Expo／React Native 版本兼容的 JDK。在 Android Studio 完成 SDK 下载和首次 Gradle 同步。Windows、macOS 或 Linux 都可以构建 Android 版本。

在项目根目录生成 Android 工程：

```sh
npx expo prebuild --platform android
```

用 Android Studio 打开生成的 `android` 目录，等待同步完成。如只需开发测试，可以连接开启 USB 调试的设备后运行：

```sh
npx expo run:android
```

开发测试构建不能直接当作正式发布版本。[Expo 本地发布构建](https://docs.expo.dev/guides/local-app-production/)

### 2. 生成正式签名安装包

在 Android Studio 选择 **Build → Generate Signed App Bundle or APK**：

1. GitHub 直接分发选 **APK**；需要 Android App Bundle 的商店选 **Android App Bundle**。AAB 不是用户直接点击安装的 APK。
2. 创建或选择自己的发布 keystore、密钥 alias 和密码。将 keystore 放在仓库之外，另做安全备份；不要使用项目的 debug 签名发布。
3. 选择 `release` 构建，生成签名产物，并通过完成提示定位输出文件。输出路径取决于构建设置，不依赖猜测的文件名。
4. 在真机安装该产物，确认不用开发服务器也能启动、连接 API、保存和恢复历史。
5. 用 Android SDK 的 `apksigner verify --print-certs` 检查最终 APK，记录签名证书指纹；为 APK 生成 SHA-256 文件校验值，便于用户核对。

签名密钥、密码、发布令牌和任何 API Key 都不能提交到仓库或放入 Release 附件。直接分发 APK 时，保管好应用签名密钥，否则可能无法向已安装用户提供正常更新。[Android 官方签名指南](https://developer.android.com/studio/publish/app-signing)
